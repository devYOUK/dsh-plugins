# 需求

## 背景与问题

0001 只搜索“当前可见”的正文：折叠的过程行在 DOM 里带 `hidden`，被排除。用户常常记得某一步过程里写过一句话，但过程折叠着就搜不到。最初用独立配置项控制，后来改为直接跟随「过程」开关。

## 目标

- 「过程」开启（默认）时，折叠的过程正文参与搜索；定位命中时自动展开并滚动到高亮。
- 「过程」关闭时与 0001 一致：折叠内容不命中、不展开。
- 只展开命中所在的分组，不展开整轮。
- 展开失败时把命中剔除，计数不虚高。
- 配置页保持三个数字字段，不新增折叠开关。

## 非目标

- 不搜索 `reasoning` 与工具调用输出。
- 不改变宿主对折叠状态的持久化。
- 不修改宿主 DOM 结构，只复用揭示入口。

## 验收标准

| # | 可观察行为 | 验收方式 |
|---|---|---|
| 1 | 「过程」默认开启，配置页没有独立折叠开关 | 配置页只有三个字段 |
| 2 | 「过程」关闭时折叠内容不命中 | 计数与 0001 一致 |
| 3 | 「过程」开启时折叠过程中的关键词能命中 | 折叠状态下搜得到 |
| 4 | 定位折叠内命中时自动展开所属分组并滚动 | 分组展开、高亮可见 |
| 5 | 跨分组只展开目标分组 | 其余分组状态不变 |
| 6 | 展开失败时该命中不计数并跳过 | 计数不虚高，导航有反应 |
| 7 | 关掉「过程」后折叠内容重新不命中 | 计数回退，界面无跳动 |
| 8 | 手动收起后下一次重算移出该命中 | 计数减少 |

## 影响面

- 客户端：`classifyContainer` / `activate` / `revealContainer`。
- 宿主 DOM 契约：`hidden="until-found"`、`beforematch`、`data-chat-motion`。
- 无 Config 新增；折叠行为跟随搜索条 `opts.includeProcess`。
