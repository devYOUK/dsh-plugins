# 0004 · 工作区右键菜单

## 背景与问题

侧栏的工作区列表每行只有一个「…」按钮，里面是重命名与删除。想在工作区目录上做两件常见的事——用系统的文件资源管理器打开它、给它改名——每次都要先找到那个小按钮。右键是桌面应用里打开这类动作菜单的惯用入口，而宿主的这一行没有注册右键菜单的 slot，也没有 contextmenu 处理。

## 目标

- 在工作区行上右键弹出菜单，含两项：「用文件资源管理器打开」「重命名」。
- 「用文件资源管理器打开」交给 Host 的原生 opener 打开该工作区目录；失败时给出可见提示。
- 「重命名」弹出输入框，预填当前标题，确认后调用工作区服务改名，侧栏标题随之更新；空标题不允许提交，失败时在对话框内提示。
- 菜单在点击菜单外、按 `Esc`、滚动、窗口失焦时关闭。
- 在非工作区区域右键不拦截，保持宿主原有的右键行为。

## 非目标

- 不改工作区的删除、排序、新建与分组逻辑。
- 不替换侧栏或工作区浏览器，不接管左键与「…」菜单。
- 不处理会话行的右键菜单。
- 首版不做键盘方向键导航与子菜单。

## 行为与验收

| # | 行为 | 验收 |
|---|---|---|
| 1 | 右键工作区行，在鼠标位置弹出两项菜单 | 右键后菜单出现，位置不超出视口 |
| 2 | 点击「用文件资源管理器打开」，系统文件管理器打开该工作区目录 | Explorer 定位到该路径 |
| 3 | 打开失败（路径不可映射 / opener 拒绝）时显示错误提示 | 出现提示，菜单关闭 |
| 4 | 点击「重命名」，弹出预填当前标题的输入框 | 输入框自动聚焦，内容为当前标题 |
| 5 | 确认重命名后侧栏标题更新；空白标题不可提交 | 标题变化；空白时按钮禁用 |
| 6 | 点击外部、按 `Esc`、滚动或窗口失焦都会关闭菜单 | 四种方式均关闭 |
| 7 | 在非工作区行上右键不弹菜单，也不阻止默认行为 | 浏览器原生右键菜单照常 |

## 影响面与风险

- Client：注册 `shell.overlay` 的一个条目（`id: workspace-menu`），自绘菜单与重命名对话框。
- 依赖宿主 DOM 契约：工作区行的 `data-row-key="workspace:<workspaceId>"`。宿主改版导致失配时，插件不拦截右键，功能静默失效而不是误伤其他区域。
- 依赖服务：`ctx.workspaces.rename(workspaceId, title)`；`ctx.remote.session.openWorkspacePath({ path })`（返回 `{ ok }` 信封，失败可能是 `ok: false` 或抛错）。
- 风险：右键监听是文档级事件，需要只对工作区行 `preventDefault`；菜单层级要高于侧栏但低于模态对话框。回滚方式是关闭插件行或卸载 bundle，不改变任何宿主状态。
- 打开目录要求 Host 能把路径映射到本机；远程/容器部署会被拒绝，按失败提示处理。
