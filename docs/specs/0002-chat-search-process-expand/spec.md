# 0002 · 折叠过程正文的搜索与自动展开

## 背景与问题

0001 交付的搜索只覆盖“当前可见”的正文：折叠起来的过程正文在 DOM 里带 `hidden`，被排除在结果之外。回看长会话时，用户常常记得某一步过程里写过一句话，但过程是折叠的，搜不到；0001 因此把「搜索并自动展开」列为开放问题和非目标。

现在要把它做成可选能力：默认保持 0001 的行为，开启后折叠过程正文也参与搜索，并在定位到命中时自动展开它所在的分组。

## 目标

- 配置页新增布尔开关 `searchFoldedProcess`（默认关，语义见下），可保存、可恢复默认。
- 关闭时行为与 0001 完全一致：折叠内容不命中、不展开、计数口径不变。
- 开启且搜索条「过程」范围开启时：折叠的过程正文参与搜索；定位命中时自动展开该命中所在的分组，滚动到命中并高亮。
- 只展开命中所在的分组，不展开整轮；上一个/下一个跨分组时逐组展开。
- 展开失败（找不到折叠头、超时后仍不可见）时把该命中从结果中剔除，计数不虚高，导航跳过它。
- 用户手动收起后，下一次重算把该命中移出结果，计数随之减少。

## 非目标

- 不搜索 `reasoning` 思考流与工具调用输出（继续排除）。
- 不展开整轮所有分组，也不改变宿主对折叠状态的持久化。
- 不修改宿主 DOM 结构，只触发现有的折叠控件。
- 不改变 0001 的光标/历史/外观配置行为。

## 行为与验收

| # | 行为 | 验收 |
|---|---|---|
| 1 | 配置页出现「折叠过程正文」开关，默认关，保存后持久化 | 保存后重开配置页仍是保存值 |
| 2 | 开关关闭时，同一关键词的命中数与 0001 一致，折叠内容不命中 | 与升级前对比计数不变 |
| 3 | 开关开启、过程范围开启时，折叠过程中的关键词能命中，计数增加 | 折叠状态下搜索能查到 |
| 4 | 定位到折叠内的命中时，自动展开所属分组并滚动到高亮处 | 分组展开、高亮可见 |
| 5 | 上一个/下一个跨分组时只展开目标分组，无关分组保持原状 | 观察其余分组状态不变 |
| 6 | 展开失败时该命中不计数，导航继续到下一个可定位命中 | 计数不虚高，点下一个有反应 |
| 7 | 关闭开关保存后，折叠内容重新不命中，已展开的分组不被插件收起 | 计数回退，界面无跳动 |
| 8 | 手动收起含命中的分组后，下一次重算该命中移出结果 | 计数减少，不再定位到隐藏处 |

## 影响面与风险

- Config：`chat-search` 命名空间新增 `searchFoldedProcess`（布尔、`volatile`）；删除该字段等同于回到 0001。
- 客户端表单模型：原先只支持数字字段（`numberSpec`），已扩展出 `booleanSpec` 与 `role="switch"` 控件，保存/恢复默认/只读语义与数字字段一致。
- 与搜索条「过程」开关的关系：搜索条是本次会话的范围开关；配置是这个范围的“深度”——过程范围关闭时配置不生效。两者不互相替代。
- 宿主 DOM 契约：`hidden="until-found"`、`beforematch`、`data-chat-motion`。展开完全复用宿主为浏览器查找预留的 `beforematch` 入口；宿主改版会让自动展开退化，兜底是“展开不了就不计入结果”。
- 风险：派发 `beforematch` 会触发展开动画与滚动锚定，展开期间测量会定位偏差；同一分组多个命中时重复派发。缓解：等待 `hidden` 移除与 `data-chat-motion` 清空（600ms 上限）后再测量，动作幂等。
- 回滚：关闭配置即恢复 0001 行为；删除字段并保存空配置可清掉持久化值。

## 开放问题

- [x] 字段名：用 `searchFoldedProcess`（描述范围）。
- [x] 默认值：保持关闭，避免升级后计数口径变化。
- [x] 展开等待：监听 `hidden` 移除与 `data-chat-motion` 清空，最多 600ms 超时；不依赖 `transitionend`。
- [x] 展开方式：对隐藏容器派发 `beforematch` 事件，由宿主的 `useSearchableHidden` 监听器触发展开，不点击折叠头。
